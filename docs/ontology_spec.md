# 노바레지스트 온톨로지 명세 v1.0

설계: 이시형 · 이 문서는 `ontology/ontology.yaml`에서 자동으로 만든다(`python ontology/make_spec.py`). 정의를 바꾸려면 yaml을 고치거나 프로그램의 편집 화면을 쓴다.

## 0. 원칙

- 온톨로지는 회사의 디지털 트윈이다. 현업이 계속 고쳐 가며 완성한다.
- 사실의 원천은 ERP와 문서다. ERP 값은 온톨로지에서 직접 고치지 않는다.
- 정의(객체·속성·연결·규칙)는 화면에서 고칠 수 있고, 모든 수정은 이력으로 남고 되돌릴 수 있다.
- 숫자는 함수가 만들고 판단은 규칙이 내린다. AI는 함수와 규칙의 결과만 인용한다.

## 1. 같은 대상을 알아보는 규칙

- 모든 객체는 ERP 문서번호를 id로 쓴다. 필터 lot은 lot 번호, 결정·사건은 출처+날짜를 id로 쓴다.
- 원재료는 ERP 코드·공급사 품명·생산 약칭 중 어느 이름으로 불러도 같은 원재료다.
- 완제품은 SKU·제품명·고객 품번 중 어느 이름으로 불러도 같은 완제품이다.
- 원재료 lot은 사내 lot 번호와 공급사 lot 번호로 찾는다. 공급사 lot의 하이픈 유무는 무시한다.
- 공급사·고객은 코드·정식 이름·줄임 이름(예 한빛폴리텍, A사)으로 찾는다.
- 별칭은 현업이 화면에서 추가할 수 있다. 같은 별칭이 두 객체에 걸리면 경고한다.

## 3. 객체 정의

### 3-1. 공급사

원재료를 파는 회사. 직거래가 기본이고 중국 공급사만 에이전시를 경유한다. '경유 에이전시'가 비어 있으면 직거래.

- 속성: 국가, 공급 분류, 평가 등급, 표준 리드타임(일), 인코텀즈, 결제 조건
- 계산 속성(물어볼 때 계산): 거래 방식, 납기 준수율, 회신 납기 대비 평균 지연(일), 최근 부적합 건수, IQC 경계·이상치 연속
- 공급사은(는) 에이전시와(과) **경유** 관계다 (없거나 하나).

### 3-2. 에이전시

중국 공급사 구매를 대행하는 수입 대행사.

- 속성: 국가, 평균 통관 일수

### 3-3. 원재료

레진·PAG·솔벤트·첨가제·포장재.

- 속성: 분류, 세부 분류, 단위, 보관 조건, 유효기간(일), 구매 리드타임(일), 안전재고 정책(개월), 위험물, 밀도(g/mL), lot 관리, 생산 약칭, IQC 전 창고, 합격 창고, IQC 기준
- 계산 속성(물어볼 때 계산): 가용 재고, 안전재고 충족 개월수, 미입고 발주 잔량
- 원재료은(는) 공급사와(과) **공급받음** 관계다 (여럿과 여럿).

### 3-4. 구매 건

구매요청 → 품의 → 발주를 하나로 묶은 구매 단위.

- 속성: 구매요청번호, 요청일, 요청 부서, 요청 사유, 품의번호, 품의 상신일, 품의 승인일, 승인자, 발주일, 수량, 단가, 금액, 공급사 품명, 납기 요청일, 공급사 회신 납기, 운송, 비고, ERP 상태
- 계산 속성(물어볼 때 계산): 요청→발주(일), 품의 소요(일), 입고 누계, 미입고 잔량, 납기 대비 지연(일), 회신 납기 대비 지연(일)
- 구매 건은(는) 원재료와(과) **주문** 관계다 (반드시 하나).
- 구매 건은(는) 공급사와(과) **발주처** 관계다 (반드시 하나).
- 구매 건은(는) 에이전시와(과) **경유** 관계다 (없거나 하나).

### 3-5. 입고

공급사에서 물건이 들어온 기록.

- 속성: 입고일, ERP 입력일, 수량(입력 단위), 입력 단위, 수량(재고 단위), 입고 창고, COA 첨부, 공급사 lot, 수기 발주번호, 비고, 상태
- 계산 속성(물어볼 때 계산): 입력 지연(일)
- 입고은(는) 구매 건와(과) **이행** 관계다 (여럿이 하나에).
- 입고은(는) 원재료 lot와(과) **생성** 관계다 (없거나 하나).
- 입고은(는) 공급사와(과) **공급사** 관계다 (반드시 하나).

### 3-6. 원재료 lot

입고 때 붙는 사내 lot.

- 속성: 공급사 lot, 제조일, 유효기간, 설명
- 계산 속성(물어볼 때 계산): 현재 위치·수량, 상태, 잔여 유효기간(일), IQC 경계·이상치
- 원재료 lot은(는) 원재료와(과) **종류** 관계다 (반드시 하나).
- 원재료 lot은(는) 공급사와(과) **제조사** 관계다 (반드시 하나).

### 3-7. 완제품·레시피

PR 제품과 1,000 L당 원재료 투입량.

- 속성: 제품군, 유효기간(일), 병당 단가, 고형분(%), 보관 조건
- 완제품·레시피은(는) 원재료와(과) **레시피** 관계다 (여럿과 여럿).

### 3-8. 작업지시

배치 하나의 생산 기록. 공정 5단계(칭량→배합→숙성→여과→충전·포장)를 포함한다.

- 속성: 배치량(L), 구분, 계획 시작일, 계획 종료일, 실제 시작일, 실제 종료일, 상태, 계획 수량(병), 생산 수량(병), 수율(%), 배합 탱크
- 계산 속성(물어볼 때 계산): 공정 기록, 자재 대기(일)
- 작업지시은(는) 완제품·레시피와(과) **제품** 관계다 (여럿이 하나에).
- 작업지시은(는) 원재료 lot와(과) **투입** 관계다 (여럿과 여럿).
- 작업지시은(는) 설비와(과) **공정 설비** 관계다 (1~5개).
- 작업지시은(는) 필터 lot와(과) **필터 사용** 관계다 (여럿이 하나에).
- 작업지시은(는) 완제품 lot와(과) **생산** 관계다 (반드시 하나).
- 작업지시은(는) 수주와(과) **연결 수주** 관계다 (없거나 하나).

### 3-9. 설비

배합 탱크, 여과 라인, 충전 라인, 칭량실, QC 장비.

- 속성: 종류, 용량, 정비 주기(일), 동시 작업 가능 수

### 3-10. 정비·중단

- 속성: 시작, 종료, 사유
- 정비·중단은(는) 설비와(과) **대상** 관계다 (여럿이 하나에).

### 3-11. 필터 lot

여과 공정 필터의 생산 lot. ERP 화면이 없어 작업 기록의 메모 칸에서 만든다. 교체 이력만 있고 재고 관리는 없다.

- 계산 속성(물어볼 때 계산): 처음 사용일, 마지막 사용일, 사용 여과 라인, 거쳐 간 배치 수
- 필터 lot은(는) 설비와(과) **장착** 관계다 (여럿과 여럿).

### 3-12. 완제품 lot

- 속성: 생산일, 유효기간
- 계산 속성(물어볼 때 계산): 현재 위치·수량, 잔여 유효기간(일), 출하 가능 고객
- 완제품 lot은(는) 완제품·레시피와(과) **종류** 관계다 (여럿이 하나에).

### 3-13. 검사

원재료 입고 검사(IQC)와 완제품 출하검사.

- 속성: 구분, 판정, 의뢰 일시, 시작 일시, 판정 일시, ERP 입력 일시, 검사자, 불합격 사유
- 측정값: 항목마다 값·하한·상한·판정을 가진다(검사 1건에 여러 측정값).
- 계산 속성(물어볼 때 계산): 검사 소요(일), 규격 대비 여유
- 검사은(는) 원재료 lot·완제품 lot와(과) **대상** 관계다 (여럿이 하나에).
- 검사은(는) 공급사와(과) **공급사** 관계다 (없거나 하나).

### 3-14. 부적합·클레임

- 속성: 구분, 발생일, 현상, 조치, 원인, 상태, 종결일, 절차
- 부적합·클레임은(는) 원재료 lot·완제품 lot와(과) **대상** 관계다 (여럿이 하나에).
- 부적합·클레임은(는) 고객와(과) **제기** 관계다 (없거나 하나).
- 부적합·클레임은(는) 원재료·완제품·레시피와(과) **품목** 관계다 (없거나 하나).

### 3-15. 고객

- 속성: 업종, 원재료 변경 시 재승인(일), 출하 가능 잔여 유효기간(일), 매출 비중

### 3-16. 고객 승인

고객×제품마다 승인받은 원재료@공급사 조합.

- 속성: 고객 품번, 승인일, 승인된 원재료@공급사
- 고객 승인은(는) 고객와(과) **고객** 관계다 (반드시 하나).
- 고객 승인은(는) 완제품·레시피와(과) **제품** 관계다 (반드시 하나).
- 고객 승인은(는) 원재료와(과) **승인된 원재료** 관계다 (여럿).
- 고객 승인은(는) 공급사와(과) **승인된 공급사** 관계다 (여럿).

### 3-17. 수주

고객 주문 줄(수주번호 × 제품).

- 속성: 수주일, 고객 품번, 수량(병), 단가, 납기 요청일, 긴급, 비고, ERP 상태
- 계산 속성(물어볼 때 계산): 출하 누계, 미출하 수량, 납기 대비 지연(일)
- 수주은(는) 고객와(과) **주문자** 관계다 (여럿이 하나에).
- 수주은(는) 완제품·레시피와(과) **제품** 관계다 (여럿이 하나에).

### 3-18. 출하

- 속성: 출하일, ERP 입력일, 수량(병), 출하 시 잔여 유효기간(일), 납기 준수
- 출하은(는) 완제품 lot와(과) **출하 lot** 관계다 (여럿이 하나에).
- 출하은(는) 수주와(과) **이행** 관계다 (여럿이 하나에).
- 출하은(는) 고객와(과) **받는 곳** 관계다 (여럿이 하나에).

### 3-19. 계획

- 속성: 종류, 버전, 작성일, 대상월, 계획월, 수량(병)
- 계획은(는) 완제품·레시피와(과) **제품** 관계다 (여럿이 하나에).
- 계획은(는) 고객와(과) **고객** 관계다 (없거나 하나).

### 3-20. 결정·사건

ERP 밖 문서에서 꺼낸 "언제, 무엇을, 왜". 언급된 객체에 붙고, 꺼낸 사실은 객체 속성으로도 저장한다.

- 속성: 날짜, 출처, 종류, 내용, 이유, 결정자
- 결정·사건은(는) 모든 객체와(과) **언급** 관계다 (여럿과 여럿).
- 꺼내는 사실: 공급처·원료 변경, 공급 지연·중단, 품질 의심·가설, 고객 요청·변경, 결정과 이유. 형식: 주어(객체) – 서술 – 값 – 시점 – 출처 – 확신도(명시/추정)

## 4. 원재료 입고 검사(IQC)

- 검사 항목: 순도, 수분, 금속 26종, 분자량 편차, 분산도
- 금속 26종: Ag, Al, As, Au, B, Ba, Ca, Cd, Co, Cr, Cu, Fe, K, Li, Mg, Mn, Mo, Na, Ni, Pb, Sn, Ti, V, W, Zn, Zr

| 분류 | 순도(%) 이상 | 수분(ppm) 이하 | 금속(원소별 ppb) 이하 | 분자량 편차 | 분산도 | 금속 측정 주기 |
| --- | --- | --- | --- | --- | --- | --- |
| 레진 | 99.0 | 500 | 10 | ±5% | 1.8 | 5 lot 중 1 lot |
| PAG | 99.5 | 300 | 5 | - | - | 매 lot |
| 솔벤트 | 99.9 | 200 | 1 | - | - | 매 lot |
| 첨가제 | 99.0 | 500 | 10 | - | - | 매 lot |
| 포장재 | IQC 대상 아님(수량·외관만 입고 확인) | | | | | |

- 규격 대비 여유가 20%보다 작으면 '합격·경계'로 본다.
- 같은 원재료·공급사 최근 lot 평균 ± 2σ 밖이면 '합격·이상치'로 본다.
- 측정하지 않은 항목은 '미측정'으로 명시한다.

## 7. 액션 (ERP 반영, 사람 승인 필수)

- `hold_fg_lot`: 완제품 lot을 보류 창고(WH-40)로 옮기는 이동 전표 생성
- `quarantine_raw_lot`: 원재료 lot을 보류 창고로 이동
- `draft_ncr`: NCR 초안 생성(대상 lot, 현상, 근거)
- AI는 제안만 하고 사람이 승인해야 실행한다. 실행 결과는 결정·사건으로 기록한다.

## 8. 갱신

- ERP 문서가 제출·수정·취소되면(웹훅) 해당 객체와 연결만 다시 읽는다.
- 재고 위치·수량은 저장하지 않고 물어볼 때마다 ERP에서 읽는다.
- 취소된 문서는 지우지 않고 '취소' 상태로 남긴다.
- 갱신마다 시각과 바뀐 객체를 기록한다.

## 9. 수정과 버전

- 화면에서 정의를 고칠 수 있다(객체·속성·연결 추가·수정, 별칭, 규칙 숫자, 사실 확인).
- 모든 수정은 누가·언제·무엇을·왜와 함께 이력에 남고 버전이 오른다(1.0 → 1.1). 되돌릴 수 있다.
- 규칙 숫자를 바꾸면 그 규칙을 쓰는 판정이 바로 다시 계산된다.
- 화면에서 고친 정의는 이 파일에 저장된다.
- 그래프 보기 두 가지 — 설계도(객체 종류 지도)와 데이터 그래프(예 클레임 lot → 공급사 펼치기).

## 10. 데이터 품질

- Q01: 입고가 구매 건에 ERP로 연결되지 않음 → '연결 끊김', 제안: 수기 발주번호로 연결
- Q02: 품의 승인일 또는 공급사 회신 납기 비어 있음 → '누락'
- Q03: 실제일과 ERP 입력일 차이 ≥ 3일 → '늦은 입력'
- Q04: 같은 공급사 lot으로 입고 2건 → '중복 의심'
- Q05: 여과 공정에 필터 lot 비어 있음 → '기록 누락'
- Q06: 고객 취소 메일이 있는데 ERP 수주가 살아 있음 → '불일치'
