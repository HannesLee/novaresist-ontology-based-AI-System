# 온트윈(Ontwin) 요구사항 (requirements.md)

버전 0.3 · 2026-11-01 · 작성: 이시형 (초안: Claude)

## 1. 목적
반도체 소재·스페셜티 화학 중소기업에서 구매·품질·생산·영업 담당자가 **ERP 화면을 오가지 않고 대화로** 업무 판단에 필요한 근거를 얻게 한다.
핵심 시나리오는 "고객 품질 클레임 → 원인 원재료·공급사 추적 → 같은 위험의 재고·출하분 파악".

## 2. 사용자
| 사용자 | 대표 질문 |
| --- | --- |
| 품질 | 이 클레임 lot에 들어간 원재료 lot과 IQC 측정값은? 같은 원재료를 쓴 다른 완제품은 어디 있나? |
| 구매 | 이 공급사 지연이 어떤 고객 주문에 영향을 주나? 공급사를 바꾸면 어느 고객 재승인이 필요한가? |
| 생산 | 자재 때문에 못 들어가는 작업지시는? 설비 보수가 어떤 주문에 영향을 주나? |
| 영업 | 이 주문 납기를 지킬 수 있나? 이 고객에게 보낼 수 있는 재고(잔여 유효기간 기준)는? |

## 3. 기능 요구사항
| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| F1 | ERPNext API로 기준정보·거래를 읽어 온톨로지 객체·링크를 만든다 | 필수 |
| F2 | ERPNext에서 문서가 제출·수정·취소되면(웹훅) 해당 객체를 다시 읽어 온톨로지를 갱신한다. 웹훅이 없으면 '마지막 동기화 이후 변경분' 가져오기로 대신한다 | 필수 |
| F3 | 온톨로지 정의는 코드가 아닌 정의 파일(`ontology/ontology.yaml`)로 관리한다: 객체, 속성, ERP 출처, 링크, 별칭, 규칙 | 필수 |
| F4 | 부서별 다른 이름(ERP 코드·공급사 품명·생산 약칭·고객 품번)을 같은 객체로 찾는다 | 필수 |
| F5 | 함수: lot 역추적, 영향 순추적, 공통 요인 비교, 고객별 출하 가능 판정, 재승인 필요 판정 | 필수 |
| F6 | ERP 밖 문서(메일·회의록·결정 기록)를 관련 객체에 연결하고, 문서에서 꺼낸 사실을 속성으로 저장한다 | 필수 |
| F7 | Claude API 챗봇: 온톨로지 도구를 호출해 답하고, 답마다 근거(ERP 문서번호·객체 id)를 표시한다 | 필수 |
| F8 | 비교 모드: 같은 질문을 'ERP 조회 도구만 가진 일반 Claude'와 나란히 실행하고 결과를 기록한다 | 필수 |
| F9 | 온톨로지 탐색 화면: 객체 검색, 속성·링크 보기 | 권장 |
| F10 | 액션: 의심 lot 출하 보류를 제안하고, 사람이 승인하면 ERP에 보류 창고 이동 전표를 만든다 | 선택 |
| F11 | 온톨로지 수정: 화면에서 객체·속성·연결·별칭·규칙 숫자를 고치고, 문서에서 꺼낸 사실을 확인·수정한다. 모든 수정은 누가·언제·무엇을·왜와 함께 이력에 남고 버전이 오르며, 이전 버전으로 되돌릴 수 있다. 고친 정의는 `ontology.yaml`에 저장된다 | 필수 |
| F12 | 그래프 보기: ① 설계도(객체 종류와 연결 지도) ② 데이터 그래프(객체 하나에서 연결을 펼쳐 보기, 예: 클레임 lot → 원재료 lot → 공급사) | 필수 |
| F14 | ERP 화면 위 챗봇: ERPNext 화면을 온트윈 안에서 그대로 보여 주고, 그 위에 챗봇 창을 띄운다. 챗봇은 사용자가 지금 보고 있는 문서(예: 발주 PO-26-0123)를 알고 "이 건"으로 질문받는다 | 필수 |
| F15 | 작업대: ERP·온톨로지 데이터를 카드(표)로 2개 이상 올려 놓고, 카드를 골라 "구매량 많은 원재료부터 단가 표 만들어 줘"처럼 요청하면 표·차트를 만든다. 계산은 AI가 쓴 코드가 데이터로 하고, 사용한 카드·필터·코드를 함께 보여 준다 | 필수 |
| F16 | 내보내기: 만든 표·차트·답변은 엑셀(.xlsx), 파워포인트(.pptx), 워드(.docx)로 내보낸다. 표는 셀 데이터, 차트는 각 프로그램에서 고칠 수 있는 차트로 넣는다(그림 X) | 필수 |
| F17 | BI 연결: 작업대 결과를 공통 데이터셋으로 저장하고, 어댑터로 BI 플랫폼에 맞게 내보낸다. 처음엔 CSV·엑셀(모든 BI 공통) + 1개 플랫폼, 나머지는 플랫폼 확정 후 추가 | 권장 |
| F13 | 데이터 품질 표시: 연결 끊김·누락·늦은 입력·중복 의심 등(정의 파일 `data_quality`)을 객체에 표시한다 | 권장 |

## 4. 비기능 요구사항
- ERP 접근은 **읽기 전용 API 키**가 기본. 액션(F10)만 별도 권한·사람 승인.
- 비밀값(API 키·비밀번호)은 `.env`에만 두고 저장소에 올리지 않는다.
- 답변은 근거 없는 수치를 만들지 않는다: 숫자는 도구 결과에서만 인용.
- 생성 코드는 읽기 전용 데이터만 받는 격리 실행기에서 돌리고, ERP에 쓰지 못한다.
- 한국어 UI, 노트북 한 대(Windows + WSL + Docker)에서 실행 가능.
- 데모 데이터는 전부 가상. 실제 회사 자료를 넣지 않는다.

## 5. 범위 밖 (이번 버전)
권한 관리·감사 로그, 그래프 DB 엔진, 다중 회사, 모바일 앱.

## 6. 완료 기준
- ERPNext에서 NCR을 등록하면 1분 안에 챗봇의 출하 판단이 바뀐다(시연 영상 장면).
- 화면에서 규칙 숫자(예: C사 출하 유효기간 90→120일)를 바꾸면 같은 질문의 판정이 바로 바뀌고, 이력에서 되돌릴 수 있다.
- ERPNext 발주 화면에서 챗봇에 "이 건 언제 들어와?"라고 물으면 그 발주 기준으로 답한다.
- 작업대에서 카드 2개로 만든 표를 엑셀·파워포인트·워드로 열어 수정할 수 있다.
- 평가 질문 6개를 일반 Claude와 본 시스템으로 각각 실행한 결과표가 있다.
- README만 읽고 다른 사람이 실행할 수 있다.
